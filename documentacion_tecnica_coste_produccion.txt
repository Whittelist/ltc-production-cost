2. FORMULA PRINCIPAL DEL COSTE DE PRODUCCION
================================================================================

  Coste por moneda = (Hashrate x Efficiency x Elec_Price x 24 x Overhead)
                     ----------------------------------------------------
                          (Blocks_per_day x Block_Reward)

2.1 Variables y unidades
-------------------------
  - Hashrate (H): Tasa de hash de la red en hashes/segundo
    * LTC: se expresa en MH/s (millones de hashes/segundo, Scrypt)
    * BTC: se expresa en TH/s (billones de hashes/segundo, SHA-256)
    * Fuente: REAL - Coin Metrics API o Blockchair

  - Efficiency (E): Eficiencia energetica de los mineros
    * LTC: J/MH (Julios por Megahash, Scrypt)
    * BTC: J/TH (Julios por Terahash, SHA-256)
    * Fuente: ESTIMADO - curva basada en ASICs comerciales

  - Elec_Price (P): Precio de la electricidad en $/kWh
    * Valor por defecto: $0.05/kWh
    * Fuente: ESTIMADO - media industrial global

  - Overhead (O): Factor de gastos adicionales (1.15 = 15% extra)
    * Incluye: refrigeracion, mantenimiento, alquiler, personal
    * Fuente: ESTIMADO - Galaxy Research (estandar industria)

  - Blocks_per_day (B): Bloques generados por dia
    * LTC: 576 (86400s / 150s/bloque)
    * BTC: 144 (86400s / 600s/bloque)
    * Fuente: PROTOCOLO

  - Block_Reward (R): Recompensa por bloque en la moneda nativa
    * LTC actual: 6.25 LTC (desde halving 2023)
    * BTC actual: 3.125 BTC (desde halving 2024)
    * Fuente: PROTOCOLO

2.2 Derivacion paso a paso
---------------------------
  Paso 1: Potencia total de la red en vatios
    Power_W = H x E
    Unidades: (MH/s) x (J/MH) = J/s = W

  Paso 2: Energia diaria en kWh
    Daily_kWh = Power_W x 24h / 1000

  Paso 3: Coste electrico diario
    Daily_Elec_Cost = Daily_kWh x P

  Paso 4: Coste total diario (con overhead)
    Total_Daily_Cost = Daily_Elec_Cost x O

  Paso 5: Monedas minadas por dia
    Daily_Mined = B x R

  Paso 6: Coste por moneda (solo electricidad)
    Cost_Elec_Only = Daily_Elec_Cost / Daily_Mined

  Paso 7: Coste por moneda (coste total)
    Cost_Total = Total_Daily_Cost / Daily_Mined

2.3 Extension para merged-mining (LTC+DOGE)
---------------------------------------------
  Cuando hay merged mining, el coste total NO se reparte uniformemente
  entre LTC y DOGE. En su lugar, se usa la proporcion de ingresos:

    ltc_share = LTC_Revenue / Total_Revenue
    doge_share = DOGE_Revenue / Total_Revenue

  Coste_LTC_asignado = Total_Daily_Cost x ltc_share
  Coste_por_LTC_asignado = Coste_LTC_asignado / Daily_LTC_Mined

  Coste_por_LTC_efectivo = Total_Daily_Cost / (Daily_LTC_Mined / ltc_share)

  Este metodo es conceptualmente superior al "bonus DOGE" porque:
  (a) No asume hashrates independientes para LTC y DOGE
  (b) Refleja la realidad del merged mining: mismo trabajo, dos ingresos
  (c) Es mas estable: no se dispara cuando los hashrates fluctuan (v. seccion 13)

6. AJUSTE POR MERGED MINING CON DOGECOIN (v2 - REPARTO POR INGRESOS)
================================================================================

6.1 Que es el merged mining?
-------------------------------
  Litecoin y Dogecoin comparten el mismo algoritmo (Scrypt).
  Los mineros de LTC pueden minar DOGE simultaneamente SIN coste
  energetico adicional (el hashrate vale para ambas cadenas).
  Esto significa que los ingresos por DOGE reducen el coste EFECTIVO
  de minar LTC.

  El punto clave: en merged mining, el MISMO hashrate asegura ambas
  redes. No son hashrates independientes. El hashrate reportado para
  DOGE (ej: 1.85 PH/s) y LTC (ej: 2.72 PH/s) son el MISMO pool de
  mineros, no mineros distintos. La dificultad de cada cadena se
  ajusta independientemente para mantener su tiempo de bloque.

6.2 Por que el metodo anterior era incorrecto (v1 - "DOGE bonus")
-------------------------------------------------------------------
  En v1, el "DOGE bonus" se calculaba como:

    ltc_rev_por_GHs = (1 / ltc_ghs) x 576 x 6.25 x ltc_price
    doge_rev_por_GHs = (1 / doge_ghs) x 1440 x 10000 x doge_price
    Bonus_DOGE = (doge_rev_por_GHs / ltc_rev_por_GHs) x 100

  El problema: al dividir por doge_ghs y ltc_ghs por separado, se
  asumia implicitamente que los hashrates son independientes.
  Como doge_ghs (ej: 1.85 PH/s) y ltc_ghs (ej: 2.72 PH/s) son
  diferentes (porque cada red ajusta su dificultad independientemente),
  el ratio doge_rev/ltc_rev era inestable y podia inflarse o
  desinflarse artificialmente.

  En la practica, cuando doge_ghs era MENOR que ltc_ghs, el bonus
  se inflaba (denominador mas chico => DOGE rev/GH/s mas alto).
  Con los datos del 27/06/2026, esto daba bonus de +1041%, y un
  coste con DOGE de solo $21.96/LTC - sospechosamente bajo.

6.3 Metodo actual (v2) - Reparto de costes por ingresos
----------------------------------------------------------
  En lugar de calcular un "bonus", se calculan los ingresos totales
  diarios de cada cadena:

    LTC_Revenue = 576 bloques x 6.25 LTC x ltc_price + LTC_Fees
    DOGE_Revenue = 1440 bloques x 10000 DOGE x doge_price + DOGE_Fees
    Total_Revenue = LTC_Revenue + DOGE_Revenue

  Donde las fees se obtienen de Blockchair en vivo:
    LTC_Fees = average_transaction_fee_usd_24h x transactions_24h
    DOGE_Fees = (mismo calculo)

  Luego se calcula la proporcion de ingresos:

    ltc_share = LTC_Revenue / Total_Revenue
    doge_share = DOGE_Revenue / Total_Revenue

  Y el coste se reparte segun esa proporcion:

    Coste_asignado_a_LTC = Total_Daily_Cost x ltc_share
    Coste_por_LTC_asignado = Coste_asignado_a_LTC / (576 x 6.25)

    Coste_por_LTC_efectivo = Total_Daily_Cost / ((576 x 6.25) / ltc_share)

  Esto es equivalente a decir: si DOGE genera el 87.6% de los ingresos,
  entonces el 87.6% del coste electrico se "paga" con ingresos DOGE,
  y solo el 12.4% restante se asigna a la produccion de LTC.

6.4 Ventajas del nuevo metodo
-------------------------------
  1. No usa hashrates para el reparto - evita el sesgo de hashrates
     "independientes" que en realidad no lo son
  2. Es estable - el ratio ltc_share/doge_share solo cambia cuando
     cambian los PRECIOS, no cuando fluctua la dificultad
  3. Es transparente - muestra directamente cuantos USD genera cada
     cadena, y que porcentaje del coste total cubre cada una
  4. Incluye fees - aunque sean pequenas, son parte del ingreso real
  5. Es mas intuitivo - "DOGE paga el 87.6% de la factura electrica"
     es mas claro que "hay un bonus del 1041%"

7.3 Impacto en el modelo
--------------------------
  Las fees son despreciables (<0.3%) para ambos activos en la actualidad.
  Sin embargo, se incluyen porque:
    - Son parte del ingreso real del minero
    - En periodos de alta congestión de red, las fees pueden llegar
      a ser significativas (ej: BTC en 2021 tenia fees del 10-15%)
    - Para que el modelo sea completo y extensible a futuro

  Para el calculo historico (2014-2026), NO se incluyen fees porque
  Blockchair no proporciona datos historicos de fees, solo el valor
  actual. En el grafico historico ajustado, las fees se asumen como
  cero, lo que subestima ligeramente los ingresos DOGE históricos.

8.3 Funcion clave: calc_merged_revenue_share()
------------------------------------------------
  def calc_merged_revenue_share(ltc_stats, doge_stats, ltc_hr_ghs):
      ltp = ltc_stats["market_price_usd"]
      dop = doge_stats["market_price_usd"]
      ltc_fees = parse_fee_usd_24h(ltc_stats)
      doge_fees = parse_fee_usd_24h(doge_stats)

      ltc_rev_total = 576 x 6.25 x ltp + ltc_fees
      doge_rev_total = 1440 x 10000 x dop + doge_fees
      total_rev = ltc_rev_total + doge_rev_total

      ltc_share = ltc_rev_total / total_rev
      doge_share = doge_rev_total / total_rev

      return {ltc_share, doge_share, ltc_revenue, doge_revenue,
              total_revenue, ltc_fees, doge_fees,
              ltc_rev_per_ghs, doge_rev_per_ghs}

  Nota: ltc_rev_per_ghs y doge_rev_per_ghs usan el MISMO denominador
  (ltc_hr_ghs = hashrate LTC en GH/s), porque en merged mining el
  mismo GH/s genera ingresos en ambas cadenas simultaneamente.

8.4 Manejo de errores
----------------------
  - Rate limiting: 300ms entre llamadas a APIs
  - Reintentos: 3 intentos con backoff exponencial
  - HTTP 429: espera 3s adicionales
  - Si una API falla: retorna None, el calculo se salta ese dia
  - Si faltan datos DOGE pre-2014: ltc_share=1.0, doge_share=0.0

8.5 Dependencias
-----------------
  - Python 3.10+
  - requests (HTTP)
  - matplotlib (graficos)
  - datetime / time / typing (stdlib)

11. LIMITACIONES Y CONSIDERACIONES
================================================================================

11.1 El modelo NO considera:
  - Costes de pool mining (comisiones ~1-2%)
  - Costes de capital (compra de ASICs, financiacion)
  - Diferencias geograficas en precio de electricidad
  - Variacion de eficiencia entre ASICs en la misma epoca
  - Revenue del merged mining con otras monedas Scrypt (BEL, etc.)
  - Impuestos, tasas, y regulaciones locales
  - Fees historicas (solo fees en vivo, no historicas)

11.2 Curvas de eficiencia:
  - Son ESTIMACIONES basadas en el ASIC mas eficiente de cada epoca
  - La eficiencia real de la red es peor (no todos usan el ultimo ASIC)
  - El modelo asume que la media de la red se acerca al ASIC lider
  - Esto es una simplificacion aceptada en la industria

11.3 Precio de electricidad:
  - $0.05/kWh es una media global
  - Mineros en Kazakhstan/Iran pagan $0.02-0.03/kWh
  - Mineros en USA pagan $0.04-0.07/kWh
  - Mineros en Europa pagan $0.08-0.15/kWh
  - Esto introduce incertidumbre de ~4x en el coste absoluto

11.4 Hashrate real vs dificultad:
  - LTC live usa: hashrate = difficulty x 2^32 / block_time
  - Esto da el hashrate ESTIMADO basado en la dificultad actual
  - No es el hashrate real exacto pero es el metodo estandar
  - DOGE live usa: hashrate_24h si disponible (Blockchair lo ofrece)
  - Fallback: mismo metodo que LTC (con block_time=60s para DOGE)

11.5 Discrepancias con fuentes externas:
  - CoinWarz daba $316/LTC (mayo 2026) vs nuestro $250.60/LTC
  - Diferencia: CoinWarz usa eficiencia promedio global mas alta
    (incluye ASICs antiguos), nuestro modelo usa eficiencia del
    ASIC lider, lo que da costes mas bajos
  - WhatToMine daba ~$90/LTC (usando L7 a $0.06/kWh) - mas bajo
    porque es un ASIC especifico NO la media de la red
  - Ambos son consistentes con nuestro modelo dentro del rango
    esperado

13. COMPARATIVA v1 vs v2 (METODOLOGIA MERGED MINING)
================================================================================

13.1 Resumen del cambio
-------------------------
  Aspecto               v1 (DOGE bonus)           v2 (reparto ingresos)
  Unidad base           GH/s de cada red          USD/dia de cada cadena
  Denominador           doge_ghs vs ltc_ghs       ltc_ghs (unico)
  Incluye fees?         No                        Si (vivo)
  Estabilidad           Baja (fluctua con diff)   Alta (solo con precio)
  Resultado 27/06       Bonus +1041%              DOGE share 87.6%
  Coste con DOGE        $21.96                    $31.06
  Valoracion consejero  No aplica (7/10)          No evaluada aun

13.2 Por que v1 daba resultados extremos
-------------------------------------------
  En v1: doge_rev_por_GHs = (1/doge_ghs) x 1440 x 10000 x doge_price
         ltc_rev_por_GHs = (1/ltc_ghs) x 576 x 6.25 x ltc_price

  Con datos reales (27/06):
    doge_ghs = 1,852,118 GH/s
    ltc_ghs = 2,723,867 GH/s
    doge_rev/GH/s = (1/1.85M) x 1440 x 10000 x 0.0758 = $0.5896
    ltc_rev/GH/s = (1/2.72M) x 576 x 6.25 x 42.85 = $0.0566
    "Bonus" = $0.5896 / $0.0566 = 1041%

  El bonus era enorme porque doge_ghs (1.85 PH/s) es MENOR que ltc_ghs
  (2.72 PH/s), haciendo que el denominador de DOGE sea mas pequeno y
  por tanto el ingreso por GH/s parezca mayor. Pero ambos hashrates
  provienen del MISMO pool de mineros - no tiene sentido dividir por
  denominadores diferentes.

13.3 Por que v2 es mas correcto
---------------------------------
  En v2, todos los ingresos se normalizan al mismo hashrate (ltc_ghs):

    doge_rev_por_GHs = (1/ltc_ghs) x 1440 x 10000 x doge_price
                     = (1/2.72M) x 1440 x 10000 x 0.0758 = $0.4009

    "DOGE share" = $0.4009 / ($0.4009 + $0.0566) = 87.6%

  Esto refleja correctamente que el mismo GH/s genera $0.4009 de DOGE
  y $0.0566 de LTC por dia. La proporcion es estable: solo cambia si
  cambian los precios, no si cambia la dificultad de alguna red.

13.4 Conclusion
-----------------
  El consejero tenia razon en los 4 puntos:
  1. Repartir por hashrate -> INCORRECTO (mismo hashrate para ambas)
  2. Bonus de +1041% -> INFLADO (por usar denominadores distintos)
  3. Formula del coste ajustado -> BIEN, pero el input (bonus) estaba mal
  4. Falta de fees -> CORREGIDO (anadidas en v2)

  El nuevo metodo de reparto por ingresos es conceptualmente mas limpio,
  mas estable, y produce resultados mas razonables ($31.06 vs $21.96).
